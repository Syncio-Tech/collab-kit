# conversation/

A spec ↔ implementation channel between two parties and their agents, managed by
[collabkit](https://github.com/Syncio-Tech/collab-kit). Read this at the start of every session.

## Layout

```
conversation/
  README.md        this file (spec-owner only)
  config.yml       parties, modes, limits (spec-owner only)
  INDEX.md         generated by `collab index`
  _templates/
  SYNC-001/
    ticket.md      frontmatter + problem statement (written once by the opener)
    01-<id>.md     one file per turn; never edit another party's turn
    99-conclusion.md
```

## Session start

1. `git pull` in this repo.
2. `collab inbox` - tickets waiting for you.
3. Act with `collab reply | conclude | sign | decide | state`.
4. `collab check`, then `collab submit` (pushes a branch + PR, or prints the
   commands for your human, depending on your `mode`). Nobody pushes to `main`.

## Levels

| level | meaning | who decides |
| --- | --- | --- |
| T0 | no product change: wording, docs, naming | implementer or spec-owner human |
| T1 | make code match the spec, or a change proven not to alter results | implementer human |
| T2 | changes results or shape; differs from spec; new feature; touches a signed document | spec-owner human |
| T3 | a shipped product is producing wrong results on real data | spec-owner human, now |

## Rules

1. The opener sets the level and a one-line reason (`level_reason`).
2. An agent may only **raise** a level. Lowering needs a human (`level_override_by`).
3. At most `max_turns_per_point` turns per point per agent. Still disagreeing → T2, and the
   options go into the conclusion.
4. Any ticket saying the code differs from the spec is T2 or higher.
5. Every ticket points to an original requirement. None → `requirement: NO_REQUIREMENT`, state `parked`.
6. Do not concede to close faster: open disagreements become options for the human, with trade-offs.
7. A conversation PR touches only `conversation/`. A spec change is a separate PR, after approval.
8. No secrets, credentials or customer data in the conversation.
9. At most `max_new_tickets_per_week` new tickets per agent per week, except T3.

## States

`open` → `discussing` → `agreed` (conclusion signed by both agents) → `approved` (human decision)
→ `in-spec` (spec PR merged + tagged) → `conformed` (code matches that tag).
Side exits: `parked` (not now) · `rejected` (no, with reason).
T0/T1 that only change the implementer's code: `agreed` → `conformed`.
